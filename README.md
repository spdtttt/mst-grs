# NEW-MST-GRS

ระบบแก้ไขผลการเรียนคงค้าง ภาษาไทย โทนม่วง ใช้ Next.js App Router, TypeScript และ Supabase PostgreSQL/Auth

## เริ่มต้น

1. ใช้ Node.js 22 ขึ้นไป แล้ว `npm install`
2. คัดลอก `.env.example` เป็น `.env.local` ใส่ Supabase URL, Publishable key และ `LOGIN_HMAC_SECRET` สุ่มอย่างน้อย 32 ตัวอักษร (ห้ามเปลี่ยนหลังสร้างบัญชีโดยไม่มีแผนย้ายบัญชี) สำหรับ Web Push ให้สร้าง VAPID key หนึ่งชุดด้วย `npx web-push generate-vapid-keys --json` แล้วตั้งค่าตามชื่อในไฟล์ตัวอย่าง
3. เปิด Supabase SQL Editor แล้วรันไฟล์ใน `supabase/migrations` ตามลำดับเลข (`001`, `002`, `003`, `004`, `005`, `006`, `007`, `008`, `009`) หนึ่งครั้ง ระบบเริ่มต้นเป็นสถานะปิด
4. ปิด Allow new users to sign up ใน Supabase Authentication เพื่อให้สร้างบัญชีผ่านเครื่องมือของโรงเรียนเท่านั้น
5. เตรียมบัญชีตามหัวข้อด้านล่างและสร้างบัญชีฝ่ายวิชาการก่อน
6. `npm run dev` แล้วเปิด http://127.0.0.1:3000 เข้าบัญชีฝ่ายวิชาการแล้วเลือกเมนูตั้งค่าเวลาเปิด–ปิดระบบ
7. `npm run build` และ `npm start` สำหรับ production บน Node.js หรือ deploy ด้วยผู้ให้บริการที่รองรับ Next.js เช่น Vercel ตั้ง environment variables บน server และใช้ HTTPS

ไฟล์ environment จริงถูกละเว้นจาก Git ห้าม commit หรือส่ง `LOGIN_HMAC_SECRET`, `SUPABASE_SERVICE_ROLE_KEY` และ `VAPID_PRIVATE_KEY`

## อัปเกรดจากระบบ 4 บทบาท

รัน `supabase/migrations/004_academic_schedule.sql` ใน Supabase SQL Editor หลังจากติดตั้ง 001–003 แล้ว จากนั้นใช้บัญชีฝ่ายวิชาการเดิมตั้งเวลาได้ทันที สคริปต์ลบบัญชี admin เดิมออกจาก profiles และ Supabase Auth พร้อมนำค่า admin ออกจาก enum ของฐานข้อมูล เก็บ audit log เดิมโดยตั้ง actor_id ของบัญชีที่ลบเป็น null หากมีผลการเรียนหรือไฟล์แนบอ้างถึงบัญชีนั้น สคริปต์จะหยุดและย้อนกลับทั้ง transaction เพื่อไม่ลบข้อมูลเหล่านั้น

หลังจาก 004 ให้รัน `supabase/migrations/005_manager_role.sql` เพื่อเพิ่มบทบาท manager และ `supabase/migrations/006_manager_dashboard_stats.sql` เพื่อเปิดสถิติแบบสรุปโดยไม่ให้เข้าถึงรายการผลการเรียนรายคน จากนั้นสร้างบัญชีจาก `data/accounts/accounts-manager.csv` โดยตรวจด้วย `npm run accounts -- data/accounts/accounts-manager.csv` และสร้างจริงด้วย `npm run accounts -- data/accounts/accounts-manager.csv --apply` ไฟล์นี้คัดเฉพาะ manager จากแถว 5 ของ `data/accounts/Book1.csv` อยู่ในเครื่องและถูกละเว้นจาก Git; เก็บรหัสผ่านอย่างปลอดภัยก่อนลบไฟล์ บัญชี manager ใช้หน้า `/dashboard/manager` หน้าเดียว โดยสลับ Dashboard สถิติ รายการที่ยังไม่เสร็จสิ้น และรายการที่เสร็จสิ้นแล้วภายในหน้าโดยไม่รีโหลดเว็บ สองส่วนรายการยังเป็นหน้าเตรียมไว้จนกว่าจะกำหนดขอบเขตข้อมูลเพิ่มเติม

## บัญชีและวิธีเข้าสู่ระบบ

| บทบาท               | ข้อมูลเข้าสู่ระบบ                                  |
| ------------------- | -------------------------------------------------- |
| นักเรียน            | เลขประจำตัวนักเรียน + เลขบัตรประชาชน 13 หลัก       |
| ครู                 | เลขบัตรประชาชน 13 หลักอย่างเดียว ตามข้อกำหนดผู้ใช้ |
| ฝ่ายวิชาการ         | เลขบัตรประชาชน 13 หลักอย่างเดียว                   |
| ผู้บริหาร (manager) | ชื่อผู้ใช้ + รหัสผ่านอย่างน้อย 6 ตัวอักษร          |

เลขบัตรประชาชนเป็นข้อมูลระบุตัวตน ไม่ใช่ความลับที่ปลอดภัย ผู้ที่ทราบเลขบัตรของครูหรือฝ่ายวิชาการสามารถเข้าสวมสิทธิ์ได้ การจำกัดความถี่ไม่ได้แก้ปัญหานี้ แนะนำเพิ่ม OTP หรือรหัสผ่านก่อนใช้งานกับข้อมูลจริง หากต้องรักษาวิธีเข้าสู่ระบบนี้ควรจำกัดการเข้าถึงเครือข่ายโรงเรียนด้วย reverse proxy ที่เชื่อถือได้

ระบบไม่เก็บเลขบัตรดิบใน profiles หรืออีเมล ใช้ HMAC พร้อม secret ฝั่ง server สร้าง auth identity และ credential สำหรับนักเรียน ครู และฝ่ายวิชาการ ส่วน manager ใช้รหัสผ่านที่ตั้งไว้ Supabase Auth เก็บ hash รหัสผ่าน ไม่ใช่การทำให้การเข้าสู่ระบบด้วยเลขบัตรอย่างเดียวปลอดภัยเท่ารหัสผ่าน การจำกัดการพยายามเข้าสู่ระบบคือ 10 ครั้งต่อบัญชีต่อ 15 นาที (รวมครั้งสำเร็จ) และใช้ rate limit ของ Supabase เพิ่มเติม

สร้าง CSV UTF-8 ในเครื่องที่เชื่อถือได้ โดยมีหัว:

```csv
role,identifier,citizen_id,full_name,classroom,password
```

- student: identifier = เลขนักเรียน, citizen_id = เลขบัตร, classroom = ห้อง
- teacher: identifier = เลขบัตร, citizen_id เว้นว่าง, full_name ต้องตรงคอลัมน์ครูผู้สอน
- academic: identifier = เลขบัตร, citizen_id/classroom เว้นว่าง
- manager: identifier = ชื่อผู้ใช้ภาษาอังกฤษ 3–40 ตัวอักษร, password อย่างน้อย 6 ตัวอักษร; citizen_id/classroom เว้นว่าง แนะนำให้เปลี่ยนเป็นรหัสผ่านยาวและไม่ซ้ำก่อนใช้งานจริง

ตั้ง `SUPABASE_SERVICE_ROLE_KEY` ใน `.env.local` บนเครื่องผู้ดูแล **ห้ามส่งในแชต ห้ามใช้ NEXT_PUBLIC\_ ห้าม commit** ตรวจข้อมูลก่อนด้วย `npm run accounts -- accounts.csv` แล้วสร้างจริงด้วย `npm run accounts -- accounts.csv --apply` เครื่องมือไม่พิมพ์เลขบัตรหรือรหัสผ่าน ไม่เขียนทับบัญชีเดิม และ rollback บัญชี Auth ถ้าสร้าง profile ไม่สำเร็จ เก็บหรือลบไฟล์บัญชีตามนโยบายข้อมูลของโรงเรียน เก็บ secret ให้สำรองและจำกัดผู้เข้าถึง

## กระบวนการ

`pending (0%) → requested (25%) → assigned (50%) → submitted (75%) → teacher_approved (75%) → completed (100%)`

- นักเรียนเห็นเฉพาะของตน ยื่นคำร้องและเปิดหน้ารายละเอียดงานเพื่ออ่านคำสั่งหรือดาวน์โหลดไฟล์แนบ ส่งงานให้ครูภายนอกระบบ
- ครูเห็นหน้าแรกเฉพาะคำร้องที่ยื่นแล้ว เปิดหน้ามอบหมายงาน ระบุกำหนดส่ง และแนบไฟล์ได้สูงสุด 5 ไฟล์รวมไม่เกิน 4 MB จากนั้นรับงานและอนุมัติพร้อมระบุเกรดใหม่ ส่งออกงานค้างได้ทุกสถานะรวมยังไม่ยื่นคำร้อง
- ครูเปิด Web Push ได้จากแถบด้านข้าง เมื่อมีคำร้องใหม่ระบบส่งข้อความทั่วไปที่ไม่มีชื่อหรือผลการเรียน กดแล้วเปิดรายการนั้น หาก session หมดอายุจะเข้าสู่ระบบก่อนแล้วกลับมายังรายการเดิม การ Logout ไม่ปิดการแจ้งเตือนเพื่อให้ครูยังได้รับข้อความหลัง session หมดอายุ หากเป็นเครื่องส่วนกลางให้กด "ปิดบนอุปกรณ์นี้" ก่อน Logout
- ฝ่ายวิชาการเห็นรายการครูอนุมัติแล้ว อนุมัติสุดท้าย นำเข้าไฟล์ และส่งออกเฉพาะที่ตน/ฝ่ายวิชาการอนุมัติครบแล้ว
- ฝ่ายวิชาการตั้งเวลาเปิด–ปิดได้แม้ระบบปิดอยู่ ส่วนการดูและแก้ไขผลการเรียนยังต้องอยู่ในช่วงเวลาให้บริการ

- ผู้บริหารเห็น Dashboard สถิติจากข้อมูลจริง โดยการ์ดนับรายการรายวิชา ส่วนกราฟนับนักเรียนแต่ละคนเพียงครั้งเดียวตามระดับชั้นล่าสุด นักเรียนที่ยังมีรายวิชาไม่เสร็จอยู่ในกลุ่มยังไม่เรียบร้อย สองส่วนรายการยังเป็นหน้าเตรียมไว้
- เวลาเปิดรวมจุดเริ่มต้น เวลาปิดไม่รวมจุดสิ้นสุด ประเมินจากเวลาฐานข้อมูล บันทึก timestamptz และแสดง Asia/Bangkok

## นำเข้าและส่งออก

รองรับ `.xlsx`, `.csv`, `.tsv` UTF-8 สูงสุด 5 MB / 2,000 แถวต่อครั้ง อ่านแผ่นงานแรกของ XLSX; ไฟล์ `.xls` ต้อง Save As `.xlsx` ก่อน บันทึกเฉพาะ 11 คอลัมน์: รหัสวิชา, ชื่อวิชา, หน่วยกิต, ชั้น/ห้อง, ครูผู้สอน, เลขประจำตัว, ชื่อ-นามสกุล, เลขที่, ปีการศึกษา, ภาคเรียนที่, ผลการเรียน

รองรับผลค้าง 0, ร, มส, มผ ต้องเตรียมบัญชีนักเรียนและครูก่อน ชื่อครูที่ซ้ำกันถูกปฏิเสธเพื่อป้องกันผูกผิดคน ตรวจชื่อนักเรียนตรงบัญชีด้วย เลขนักเรียนควรเป็นข้อความเพื่อรักษาศูนย์นำหน้าใน Excel นำเข้าแบบ atomic: ผิดหนึ่งแถวจะไม่บันทึกทั้งชุด ข้ามรายการซ้ำตามนักเรียน/วิชา/ปี/ภาค โดยไม่เขียนทับความคืบหน้า ไฟล์แม่แบบดาวน์โหลดจากหน้า Import

ส่งออก CSV UTF-8 BOM เปิดใน Excel ได้ ใส่ apostrophe ก่อนค่าเสี่ยงเป็นสูตร รายงานสำเร็จมีเกรดใหม่และเวลาที่ฝ่ายวิชาการอนุมัติ

## ความปลอดภัยและการใช้งานจริง

- RLS ควบคุมข้อมูลตามเจ้าของและบทบาท ไม่มีสิทธิ์ insert/update/delete ตารางโดยตรงผ่าน client
- ไฟล์มอบหมายเก็บใน Supabase Storage bucket แบบ private ใช้ signed URL อายุ 10 นาที และ policy จำกัดเฉพาะนักเรียนเจ้าของรายการ ครูเจ้าของวิชา และฝ่ายวิชาการ
- เปลี่ยนสถานะผ่าน PostgreSQL RPC เท่านั้น ตรวจบทบาท เจ้าของ สถานะเดิม เวลาระบบ และล็อกแถวป้องกันการอนุมัติซ้ำพร้อมกัน
- ไม่มีสิทธิ์แก้บทบาทตนเอง บัญชีสร้างด้วย service role เฉพาะเครื่องมือ offline
- Auth cookies เป็น HttpOnly, SameSite=Lax, Secure ใน production; Next.js server actions ตรวจ origin โดย framework
- ปิด indexing, ไม่ cache หน้าใช้งาน, มี security headers, ไม่ใช้ `dangerouslySetInnerHTML`
- Audit log สำหรับทุก transition/import/การตั้งเวลา ไม่มีเลขบัตรประชาชน ไม่มี public registration
- Web Push เก็บ endpoint แยกตามครูและอุปกรณ์ ใช้ service role เฉพาะฝั่ง server เพื่อนำส่ง และลบ endpoint ที่หมดอายุเมื่อบริการ Push ตอบกลับว่าใช้ไม่ได้
- `/demo` ใช้ข้อมูลสมมติแยกจากฐานข้อมูล เปลี่ยนแปลงในหน่วยความจำเท่านั้น รีเฟรชจะรีเซ็ต ไม่ใช้ทดแทนการทดสอบฐานข้อมูลจริง
- ต้องทดสอบบัญชีจริงครบสี่บทบาทด้วย staging, เปิด backup/PITR ตามแผน Supabase, ตั้ง monitoring, จำกัดผู้ถือ service role และทบทวนนโยบายข้อมูลก่อนเปิดบริการ

Web Push ต้องใช้ HTTPS ใน production ครูต้องอนุญาตการแจ้งเตือนในเบราว์เซอร์ ส่วน iPhone/iPad ต้องเพิ่มเว็บไซต์ไว้ที่หน้าจอโฮมก่อนจึงเปิดรับ Web Push ได้

## ตรวจสอบ

### สไตล์และ Tailwind CSS

ใช้ Tailwind CSS v4 ผ่าน `@tailwindcss/postcss` สำหรับสไตล์ทุกหน้า รวมถึง responsive, focus, disabled และแถบความคืบหน้า ไม่มี CSS component แบบเดิมหรือ inline style ในโค้ดแอป

- `src/app/globals.css` มีเฉพาะการนำเข้า Tailwind และ `@theme` สำหรับสี ฟอนต์ และ breakpoint
- คลาส Tailwind อยู่ใน `className` ของแต่ละ element โดยตรง ไม่มีไฟล์หรือตัวแปรแยกเก็บชุดสไตล์
- สถานะที่เปลี่ยนตามข้อมูลใช้เงื่อนไขภายใน `className` และ `twMerge()` จาก `tailwind-merge` จัดการคลาสที่ทับกัน
- ใช้ชื่อคลาสแบบเต็มในแต่ละสถานะ เพื่อให้ Tailwind ตรวจพบตอน build; ฟอนต์ไทยโหลดจาก `@fontsource-variable/noto-sans-thai`

### คำสั่งตรวจสอบ

`npm test` ตรวจ state machine, ตารางเวลา, CSV injection, import validation และ auth identity

`npm run typecheck` และ `npm run build` ตรวจ TypeScript และ production build

`npx tsx scripts/check-connection.ts` ตรวจเชื่อมต่อแบบไม่แสดง key; ไม่มี migration จะขึ้น PGRST205

แนวทาง SSR ตาม [Supabase SSR](https://supabase.com/docs/guides/auth/server-side/creating-a-client) และ [Next.js Proxy](https://nextjs.org/docs/app/getting-started/proxy)

## สิ่งที่ต้องติดตั้งใน Supabase

Publishable key ไม่สามารถสร้างตารางหรือสร้างบัญชีผู้ใช้ได้ จึงต้องรัน SQL และ provision บัญชีโดยผู้มีสิทธิ์โครงการก่อน การมีหน้าเว็บและเชื่อม API ได้ยังไม่ใช่การติดตั้งฐานข้อมูลสำเร็จ

สำหรับการ์ดสถิติจำนวนนักเรียน ให้รัน `supabase/migrations/007_manager_student_counts.sql` หลัง 006 เพื่อรวมจำนวนนักเรียนที่เสร็จสิ้น/ยังไม่เสร็จสิ้นทั้งหมด รวมผู้ที่ไม่มีระดับชั้น ม.1–ม.6 โดยนักเรียนจะเสร็จสิ้นเมื่อฝ่ายวิชาการอนุมัติครบทุกวิชา

สำหรับสรุปจำนวนรายการคงค้างแยกตาม 5 สถานะบนหน้า Dashboard ผู้บริหาร ให้รัน `supabase/migrations/008_manager_outstanding_statuses.sql` หลัง 007 โดยแสดงเฉพาะจำนวนรวมและไม่เปิดเผยข้อมูลนักเรียนรายบุคคล
